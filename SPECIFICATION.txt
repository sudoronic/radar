Build a production-ready web application called **Radar**.

Radar is a personalized opportunity-discovery platform for students, young professionals, developers, founders, and other users who want to discover relevant opportunities happening in their city or online.

The product should NOT behave like a generic event directory.

The core idea is:

**“Opportunities find you.”**

Users select their interests, city, background, preferred opportunity categories, budget, experience level, and other preferences. Radar then automatically discovers relevant public opportunities from trusted internet sources, stores them in the database, removes duplicates, keeps them updated, calculates personalized relevance, and shows each user a simple personalized feed.

The application must be extremely simple, fast, aesthetic, responsive, and optimized for free-tier infrastructure.

+25

+15

-100

-20

The precise weights should be configurable in code.

Cache recommendations only if required later.

# 22. SOURCE REFRESH SYSTEM

Use Supabase Cron.

Do not attempt to refresh every source constantly.

Each source should have:

refresh_interval_minutes

next_refresh_at

The scheduler should select only sources that are due.

Example process:

Cron runs hourly.

↓

Query active sources where:

`next_refresh_at <= NOW()`

↓

Take small batch

↓

Invoke Edge Function

↓

Fetch source

↓

Extract opportunities

↓

Normalize

↓

Store/update

↓

Calculate next refresh time

Use small batches to stay safely inside Supabase free-tier execution limits.
